# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

**SLIDEREP** is a CrossFit judging app for mobile. It lets a coach or peer judge count reps during a WOD (Workout of the Day), marking each rep as valid or no-rep, while tracking progress through rounds, exercises, and stations. The name comes from the gesture-based rep input.

The app supports four classic CrossFit WOD formats:
- **For Time** (FRAN 21-15-9: thrusters + pull-ups) — elapsed timer
- **AMRAP** (CINDY 12-min: pull-ups, push-ups, air squats) — countdown timer
- **EMOM** (10-min alternating: burpees + KB swings) — per-minute countdown
- **Chipper** (FILTHY FIFTY: 10 stations × 50 reps) — elapsed timer

## Commands

```bash
pnpm start             # Start Expo dev server
pnpm start:clear       # Start Expo dev server with the Metro cache cleared
pnpm android           # Run on Android emulator
pnpm ios               # Run on iOS simulator
pnpm web               # Run in browser
pnpm lint              # Run ESLint
pnpm test              # Run the engine tests (vitest, tests/ — pure TS only, no screens)
pnpm reset-project     # Reset to blank Expo template
```

`tests/goldens.test.ts` pins every v1 result (score + splits, with and without adjustments) for synthetic logs in `tests/fixtures.ts` — against the built-ins, or against its `SYNTHETIC_WORKOUTS` for cases no built-in has (the capped For Time cases, the 90 s / 120 s EMOMs, the two-exercise-minute EMOM) —, as file snapshots in `tests/__goldens__/`, recorded on the engine as shipped — quirks included. Never re-record them with `vitest -u`: a different result means a new engine version, not an updated golden. Add a new case instead of editing a recorded one. The one exception: a golden that pins a deviation from the spec may be corrected by hand, only on its wrong lines, in a change of its own that lists each corrected line (first used by `fix-amrap-partial-reps`, the AMRAP "+ N").

## Architecture

**Stack**: Expo 58 + React Native 0.88 + TypeScript 6 + Expo Router 58 (react-native-gesture-handler 3, judging still on its builder `Gesture.*` API)

### Routing

File-based routing via Expo Router. All routes live in `app/`:
- `app/index.tsx` — the hub (B21). A header row (app name + an adaptive shortcut: "MY QR" → `/my-qr` if a profile exists, else "PROFILE" → `/profile`), a real "NEW SESSION" button to `/session/wod`, and real "HISTORY" (B23), "LIBRARY" (B24) and "SETTINGS" (B25) rows to `/history`, `/library` and `/settings` — no disabled placeholder rows left, B25 was the last backlog item. On mount, checks `hooks/use-first-run.ts`'s `firstRunDone` flag (B22) — `router.push('/first-run')` if it's unset and there's no profile yet; if a profile already exists (e.g. created before this flag existed) it backfills the flag silently instead of prompting. The hub stays mounted under the prompt, so its own `useProfile`/`useFirstRun` copies go stale: it refetches the profile in a `useFocusEffect` (keeps the shortcut right after creating/deleting one elsewhere), never blanks itself waiting on first-run, and a `promptedRef` guard pushes the prompt at most once per launch (hardware back leaves the flag unset, so it's asked again only on the next launch)
- `app/first-run.tsx` — one-time "Create profile" / "Continue anonymous" prompt (B22), pushed from the hub. "CREATE PROFILE" marks the flag done then `router.replace('/profile')` (so `/profile`'s own ✕ returns to the hub, not back here); "CONTINUE ANONYMOUS" marks it done then `router.back()`. No way to dismiss without picking one — a raw hardware-back leaves the flag unset, so it's just asked again next launch, matching "it can be skipped... profile created later" (decided in *Design: screens and routes*)
- `app/history/index.tsx` — list of "own" sessions (B23; the owner was the judged athlete — a `judge`-role session where the *other* person was judged never appears here, per the decided design). `useFocusEffect` + `db/sessions.ts`'s `getOwnSessions` (refetches on return from a delete in the detail screen), then one `db/workouts.ts` `getWorkout` per distinct `wodId` (`Promise.all`), rows rendered from the resulting id → config map. Each row shows the WOD, a local date formatter (no `Intl` dependency), and a quick unadjusted score (`deriveResult`) — the detail screen is what shows the accurate, possibly-adjusted one. - `app/library/index.tsx` — WODs + Exercises list (B24; no longer read-only since change `wod-editor`). Mode/name/duration header ("MINE" tag when own), then `config.exercises` (`{ name, detail, note? }`, from `wod-engine.ts`'s `summarize()`) — the same per-exercise breakdown `start-overlay.tsx` renders pre-judging. Actions (change `wod-editor`): DUPLICATE for any workout (gated by `withProfile`, → `/library/new?from=<id>`), and ARCHIVE only when `isOwn` (destructive `Alert.alert`, `archiveWorkout`, then `router.dismissTo('/library')` so archiving a just-saved copy doesn't land on its source). Still no link into `/session/*`: judging starts only from workout selection

#### The session flow (`app/session/`, B21)

`session/_layout.tsx` wraps the whole group in `hooks/use-session.tsx`'s `SessionProvider` (an in-memory React context — the project's first) and sets `gestureEnabled: false` on its own nested `Stack` (blocks the OS edge-swipe-back across the whole flow; every screen here has its own explicit ✕/back-link exit instead). A nested Stack doesn't inherit the root's `screenOptions`, so `headerShown`/`contentStyle` are repeated here too.

- `session/wod.tsx` — pick a WOD from the DB (`hooks/use-workouts.ts`, refetched on focus; a `ScrollView`, built-ins then own workouts tagged "MINE" — no create entry here, workouts are created from the Library); a tap calls `useSession()`'s `setWorkout(workout)` (the already-built `{ id, config }`) and pushes `/session/setup` with no params — any future entry point into the flow does the same
- `session/setup.tsx` — the owner picks their role (judge / judged), then scans the other person's QR or skips (`components/session/scan-person.tsx`), then calls `useSession()`'s `setSetup({ role, otherId, otherAlias })` (`otherId`/`otherAlias` are real `string | null` now, not the `''`-sentinel route params they used to be) and `router.replace('/session/run')`. Reads the workout (header mode/name) from the context's `workout`, never a route param, and redirects to `/session/wod` when there isn't one — no fallback workout. Shows "This session won't be saved" in both unsaved cases (see `docs/ROADMAP.md`'s Users table), as two phases sharing one render: `skipBanner` when judging and skipping (CONTINUE starts the session, GO BACK → scan), and `noProfileBanner` when choosing "I'll be judged" with no local profile (CONTINUE → scan, GO BACK → role). Reads `hooks/use-profile.ts`'s local profile to pass `selfId` to `ScanPerson` (self-scan block), and renders nothing until it has loaded so a fast tap can't show the no-profile warning to someone who has a profile
- `session/run.tsx` — judging mechanics only (what used to be `app/judge/[id].tsx`'s `ready`/`judging` phases): split into a guard (`RunScreen`: context, fonts, redirect) and an inner `RunSession` that mounts only once `workout` and `setup` exist, so `useJudge(workout.config)` always gets a real config at mount (no fallback workout); the countdown/judging UI, abort (timer tap or hardware back while judging — `Alert.alert('Abort session?', ...)`). Redirects to `/session/wod` if reached with no `workout`/`setup` in context (e.g. a direct deep link — there's nothing to resume). On `judge.finished`, stashes `{ log, startedAt, endT }` into `useSession()`'s `setOutcome(...)` and `router.replace('/session/result')` — no judge-identity derivation or saving here, that's `session/result.tsx`'s job entirely
- `session/result.tsx` — derives `judgedAthleteId`/`judgedAlias`/`judgeId`/`savedState`/`canAdjust` from `useSession()`'s `setup` + `hooks/use-profile.ts` (same logic `judge/[id].tsx` used to have), saves the session via `db/sessions.ts`'s `saveSession` (`wodId: workout.id`, `engineVersion: workout.config.engineVersion`) — only when `judgedAthleteId` is non-null (an anonymous judged athlete is never saved, per the Users table) — captures the returned id into `setSessionId`, and renders `<ResultScreen>` with it. Tracks the save outcome in a local `saveStatus` (`pending`/`saved`/`failed`) so `savedState` follows what actually happened: `'saving'` ("Saving…") until `saveSession` settles, `'failed'` ("Couldn't save this session", no retry — ADJUST RESULT stays hidden for free since `sessionId` is never set) on error, `'own'`/`'foreign'` on success, `'none'` immediately when nothing is saved. A header-row ✕ (same pattern as `history/[id].tsx`, which is why it lives here and not in `ResultScreen`) calls `router.dismissTo('/')` to close the whole session flow back to the hub; hardware back still goes to `/session/wod`. Redirects to `/session/wod` if reached with no `workout`/`setup`/`outcome` in context
- `session/adjust.tsx` — post-judging adjustment screen (B12), reached only from the result screen's "ADJUST RESULT" button (`components/result/result-screen.tsx`), once, right after finishing. Fully DB-driven from a `sessionId` route param alone (`db/sessions.ts`'s `getSession` + `db/session-adjustments.ts`'s `getAdjustments`) — doesn't touch the session context at all. Each split row is tappable to set a new target for that position, plus a duration field when the format has one (AMRAP seconds; EMOM whole minutes, or intervals labelled INTERVALS when its interval isn't 60 s, stored either way as `newDurationSeconds`; a capped For Time's cap in seconds labelled TIME CAP); "SAVE PACKAGE" writes one `session_adjustments` row (`addAdjustment`), up to 3 per session

### WOD System

- `constants/wod-engine.ts` — the interpreter ("format = behavior"). `Format` (built-in, versioned: `repeat: rounds | cycle | perInterval`, `advance`, `timer`, `stop`, `score`) and `FORMATS` (the built-ins by id, what a stored block's `formatId` resolves to — the `formats` table is never read) + `WodDefinition` (`{ id, name, block }`)/`Block`/`WodLine` (declarative WOD content; a line carries `exerciseId` + its resolved `exercise` name, `target`, and the descriptive-only `repDescription?`/`load?`) + `buildWodConfig(definition, format): WodConfig`. `WodConfig` is structure and presentation only — `mode` ("FOR TIME", "12-MIN AMRAP", "EMOM · 10", "E2MOM · 8", "EVERY 1:30 · 10" — a 1-round Chipper is just FOR TIME, still showing station progress; a For Time whose rounds all repeat the first is "5 ROUNDS FOR TIME", with each exercise's reps shown once), `description` (the one-line card text, e.g. "21-15-9 · thrusters + pull-ups"), `exercises` (`WodExercise = { name, detail, note? }` from `summarize()`; `note` joins a line's rep description and load, e.g. "500 m · 95/65 lb", absent for every built-in; a 1-rep line with a rep description shows it as the `detail` instead, "500 m"), `timerMode`, `totalSeconds`, `advanceMode`, `engineVersion`, and the `format`/`block` data the engine reads; no behavior functions. Positions are `WodSession`s (round/line, or interval + line for EMOM — the interval index is still called `minuteIdx`, the line within it is `exIdx`) read through pure helpers (`START_POSITION`, `targetAt`, `exerciseNameAt`, `kpiAt`). **The engine** is one incremental fold used by both live judging and results (change `unified-engine`): `initial(config)`, `advanceTo(config, state, t)` (clock transitions), `apply(config, state, event)` (moves the clock to the event's `t`, then counts it), `view(config, state)` (exercise, target, count, KPI, timer text) and `fold(config, events, endT)` (sorted events reduced with `apply`, then `advanceTo(endT)` — the result side). `EngineState` keeps every event `tagged` with the position it was applied at (what adjustments' no-re-flow rests on). The v1 rules per `repeat`, pinned by `tests/__goldens__/`: `rounds` finishes on the last rep and ignores later events, or — with a time cap (change `for-time-cap`) — at the cap, where a rep at the cap or later doesn't count; `cycle` (AMRAP) finishes at its duration but still counts events after it (only old logs have them — live drops gestures once finished); `perInterval` (EMOM) takes the interval from the clock, caps the live `done` but keeps the uncapped `raw`, and ignores reps at or after its last interval. **Several exercises per interval** (change `emom-multi-exercise-intervals`): a sequence entry's lines (`intervalLines(config, m)`) are done in order — `apply` moves to the next line when one reaches its target, the last line takes any extra reps (`raw` is per line), and an interval change resets `exIdx` to 0; `intervalLineAt(config, m, k)` is that rule as a pure function (the line the `k`-th valid rep of interval `m` counts toward), shared with adjustments. `summarize` shows one row per entry, names and amounts joined by " + " ("PULL-UPS + PUSH-UPS", "5 + 10 / min"). **Interval length** (change `emom-interval-length`): an EMOM block's optional `intervalSeconds` (10–600, stored only when not 60) — `intervalSeconds(config)` (`?? 60`) is the one place every interval computation reads (index `floor(t / interval)`, count `ceil(totalSeconds / interval)`, the timer), and `intervalUnit(config)` names it `'minute'` at 60 s or `'interval'` otherwise (KPI label, timer `min left`/`interval left`, `Minute N`/`Interval N` splits, the exercise detail `10 / min`/`10 / interval`); `durationSeconds` stays the whole workout (`rounds × interval`), the description is `10 × 1:30 · …` when it isn't 60 s, and `engineVersion` stays 1. **Time cap** (change `for-time-cap`): a For Time / Chipper block's `durationSeconds` is its cap, so `totalSeconds > 0` on a `rounds` config means capped — `capSeconds(config)` is the one check for it, and `isComplete(config, state)` tells a finish on the last rep (a completed For Time stays on its last position at its full count) from a finish at the cap. A capped workout's timer label is `elapsed · cap 10:00`, its description ends `· 10 min cap`, its `mode` is unchanged, and `engineVersion` stays 1 (no recorded log was ever judged against a cap). Also `formatTime`. Owns the `WodConfig`/`WodSession`/`WodKpi`/`WodExercise` types. No progressive reps, rest steps or multi-block WODs yet (changes C2b-3–C2d).
- There are no workout definitions in code: workouts come only from the DB (`db/workouts.ts`), and the v2 seed (`db/seeds/v2-builtins.ts`) is the only copy of the four built-ins. Workout ids are plain strings (the built-ins keep `fran`/`cindy`/`everyMinute`/`filthyFifty`, which `sessions.wodId` stores).
- `constants/hf.ts` — design tokens (colors, etc.) used throughout the UI

### Judge Screen Components (`components/judge/`)

The judging screen follows the **"Ghost · base"** design from Claude Design (a local copy of the handoff bundle lives in `design/`, which is git-ignored). Layout, top to bottom: header · exercise name · swipe band · count. Only the swipe band receives gestures.

- `types.ts` — `LogEntry` (`{ id, ok, t }`): one recorded gesture, `t` in ms on the session clock, which starts when judging begins (right after the countdown) — this raw log is what gets saved and what `components/result/` folds into splits and a score. There is no judging reducer: the state machine is the engine's `apply`/`advanceTo` (`constants/wod-engine.ts`), driven by `hooks/use-judge.ts`
- `judge-header.tsx` — timer (elapsed / countdown / per-minute depending on WOD type) on the left; round / minute / station progress with `round-pips.tsx` on the right. The timer block (label + time) is a `Pressable` calling `onAbortPress` — the only tap target outside the swipe band, wired in `app/session/run.tsx` to an `Alert.alert('Abort session?', 'Data will be lost.', …)` confirmation; Android's hardware back button triggers the same alert while judging is in progress
- `round-pips.tsx` — row of squares: done (filled), current (ink outline), pending (hairline outline)
- `exercise-name.tsx` — current exercise name, shrinks to fit, turns accent after a no-rep; shows "DONE" once finished. Not interactive — AMRAP/EMOM auto-finish when the clock reaches 0, exactly like For Time/Chipper already auto-finish on the last rep, so there is no manual confirmation tap anymore
- `swipe-band.tsx` — the only interactive surface: swipe right = rep, swipe left = no-rep, tap = rep; edge ticks, a breathing dot that follows the finger and a travel line after each gesture
- `count-readout.tsx` — large rep count, plus reps left and the target
- `side-rails.tsx` — full-height edge lines (accent after a no-rep) and a strip that sweeps inward after each gesture
- `start-overlay.tsx` — pre-judging WOD summary (each exercise with its reps, plus its `note` as a dim second line when it has one) and 10-second countdown (with sound cues); shows who's being judged, flipped by the `role` prop (`athleteAlias` + `role: 'judge'|'judged'` → "Judging X" / "Judged by X")

### Workout Editor (`components/editor/`)

- `draft.ts` — the editor's state as pure data (vitest-covered in `tests/draft.test.ts`): `Draft` = `ForTimeDraft` (`rounds`, `sameReps`, `cap` — time cap in whole minutes, `''` for none, saved as the block's `durationSeconds` —, `rows` with reps per round) / `AmrapDraft` (`minutes`, `rows`) / `EmomDraft` (`every` — interval seconds, `'60'` by default —, `intervals`, `slots: RepsRow[][]`, the interval sequence, each interval a non-empty list of lines, cycled; changes `emom-interval-length`, `emom-multi-exercise-intervals`). Every line helper takes the flat index into `draftLines` (`slots.flat()` for EMOM); `addLine` appends a new interval, `addLineToSlot` a line to one, and `removeLine` drops an interval left empty. Number fields stay the strings typed into the form. Pure updates (`switchFormat`, `setSameReps`, `addLine`/`removeLine`/`updateLineFields`/`setLineReps`), `setRepDescription` (adding one fills the line's empty reps with 1), `validateDraft` (problems keyed `name`/`rounds`/`cap`/`minutes`/`every`/`intervals`/`lines`/`line:<i>`; `parseInterval` is the 10–600 check), `draftToStoredBlock` (the stored layout the built-ins use — For Time one entry per round, AMRAP one entry, EMOM one entry per interval holding its lines, with `rounds` = intervals, `durationSeconds` = intervals × every, and `intervalSeconds` only when it isn't 60, so a 60 s EMOM is stored like the built-in) and `draftFromBlock` for DUPLICATE (throws for a For Time whose rounds don't share their exercises — none exists). `savedName` trims and upper-cases
- `profile-gate.ts` — `withProfile(profile, go)`: runs `go` with a profile, otherwise an alert explaining workouts need one, with a "Create profile" button to `/profile` (used by the Library's NEW and DUPLICATE)
- `exercise-picker.tsx` — `ExercisePicker`: a full-screen `Modal` over `useExercises()`'s catalog, case-insensitive substring search, grouped by `EXERCISE_CATEGORIES`; hardware back closes it

### Session Setup Components (`components/session/`)

- `scan-person.tsx` — `ScanPerson`: used by `app/session/setup.tsx` after the role choice. "SCAN QR" (requests camera permission then, via `expo-camera`'s `CameraView`) or "SKIP — ANONYMOUS". ### Result Screen (`components/result/`)

Shown by `app/session/result.tsx` (B21 split this out of what used to be `app/judge/[id].tsx`'s inline finished-phase render).

- `replay.ts` — `deriveResult(config, log)`: pure, derives score + splits from the engine's `fold(config, log, Infinity)` — the very fold live judging steps through (`constants/wod-engine.ts`), so there is no separate walk of the log here: onTarget splits come from the fold's counted events grouped by the position they were applied at, EMOM splits one per line of each interval from counted events per `(minuteIdx, exIdx)`, an interval completed only when all its lines are, labelled by `intervalSplitLabel` ("Minute N — X" at 60 s, "Interval N — X" otherwise), the score from the final state — `CAP · N reps` (N = every counted rep) for a capped For Time that ended at its cap without `isComplete`. Nothing is stored; everything here is recomputed from `WOD + log` (see `docs/ROADMAP.md` → Exercise sessions). Each `Split` carries its `(roundIdx, exIdx)` position (interval index as `roundIdx`, its line as `exIdx`, for onClock/EMOM) — unused by `result-screen.tsx` itself, consumed by `adjust.ts`/`session/adjust.tsx` (B12).
- `adjust.ts` — `deriveAdjustedResult(config, log, changes)`: B12's adjusted-result derivation. Delegates straight to `deriveResult` when `changes` is empty. Otherwise: for onClock (EMOM) formats, position *is* time (`Math.floor(t / intervalMs)`, from `intervalSeconds(config)`), so target/duration overrides apply directly per interval bucket, and a duration override scores `ceil(cutoff / interval)` intervals; within a bucket, reps are placed on lines in time order by the *original* targets (`intervalLineAt`, as live — also for reps after the original end that a raised duration brings in), so a target override (keyed `(interval, line)`) only changes completion, never moves a rep. For onTarget formats (For Time/Chipper/AMRAP), first takes each counted event's position from the engine fold over the *unmodified* config (`tagOnTargetPositions`, a thin map over the fold's `tagged`) — this is what keeps a target change from "re-flowing" later events into a different round/line, per `docs/ROADMAP.md`'s Exercise sessions decision — then applies target/duration overrides only within each position's own fixed bucket of events. For a capped For Time (change `for-time-cap`), a duration override is the adjusted cap and the edge is `t < cap`, as live (uncapped formats keep `t <= cutoff`, pinned by the AMRAP/EMOM goldens); its score is TIME only when every position of the block is complete — positions never reached count as incomplete — and `CAP · <kept reps> reps` otherwise. Uncapped For Time keeps its `DNF — …` fallback.
- `result-screen.tsx` — renders the `WodResult`: score, then a scrollable split list. Also takes `athleteAlias` + `role` to flip "Judging X" / "Judged by X", same as `start-overlay.tsx`, and a `saved: 'own' | 'foreign' | 'none' | 'saving' | 'failed'` prop that renders the decided banner copy ("Saved in your history" / "Saved on this phone — will be delivered to X once sync exists" / "Not saved" / "Saving…" / "Couldn't save this session" — the last two only ever passed by `session/result.tsx`, `history/[id].tsx` always passes `'own'`). New props `sessionId`/`canAdjust` (B12): loads this session's `session_adjustments` (`db/session-adjustments.ts`, refetched via `useFocusEffect` so returning from `/session/adjust` updates the score) and feeds them into `deriveAdjustedResult`; shows an "ADJUST RESULT" button to `/session/adjust` while `canAdjust` and fewer than 3 packages exist.

### Storage (`db/`)

- `migrations.ts` — `migrateDbIfNeeded(db)`, passed as `SQLiteProvider`'s `onInit` in `app/_layout.tsx`. `PRAGMA user_version`-based, forward-only, cascading (a fresh install runs every block in one call). Schema v1: all tables from `docs/ROADMAP.md`'s Storage & persistence schema draft are created up front, though only `sessions` has a consumer at that point. Schema v2 (B18): seeds `formats`/`exercises`/`workouts` from the frozen `seeds/v2-builtins.ts` snapshot, then rebuilds `sessions` (SQLite has no `ALTER TABLE ADD CONSTRAINT`) to add `wodId REFERENCES workouts(id)`, preserving any v1 rows — `device`/`athlete_profile` still wait for B19. `PRAGMA foreign_keys` is forced `OFF` around that rebuild (can't toggle mid-transaction) and set `ON` once, unconditionally, at the very end of the function. Schema v3 (B22): adds `app_state`, a single-row table (`id = 1`) for the `firstRunDone` flag — the only app-wide flag that exists so far. Schema v4 (B23): a plain `ALTER TABLE sessions ADD COLUMN judgeAlias TEXT` (no rebuild needed this time, unlike v1→v2 — SQLite supports `ADD COLUMN` directly) — an alias snapshot for the judge, symmetric to the existing `judgedAlias`, needed so History's detail view (opened long after the live session context is gone) has something to show. Schema v5: `ALTER TABLE exercises ADD COLUMN category TEXT` (`GYMNASTICS`/`WEIGHTLIFTING`/`MONOSTRUCTURAL` — nullable in SQL, required in app code), fills it in for v2's 14 exercises and inserts the other 69 built-ins of the 83-exercise catalog, one transaction.
- `app-state.ts` — `getFirstRunDone`/`setFirstRunDone` against `app_state` (B22). No-row read means "not done," same convention as `athlete_profile`; wrapped for screens by `hooks/use-first-run.ts`'s `useFirstRun()` (`{ done, loaded, markDone }`).
- `seeds/` — frozen, never-edit literal seed data, one file per migration that seeds: `v2-builtins.ts` (exactly the 3 `formats`/14 `exercises`/4 `workouts` rows B18's since-removed `seed-builtins.ts` derived from the since-removed `constants/wods.ts` — frozen so code changes can't alter what a fresh install seeds; it's now the only copy of the four built-in workouts) and `v5-exercises.ts` (categories for those 14 + the 69 new built-in exercises). Exercise ids are `slugify(name)` written out literally (e.g. `"KB SWINGS"` → `kb-swings`); workout ids are the built-ins' original string ids (`sessions.wodId` stores them, since B15). A catalog change is a new migration with a new seed file.
- `exercises.ts` — `getExercises(db)`: every non-archived exercise (`{ id, name, category }`, ordered by name), plus `ExerciseCategory` and `EXERCISE_CATEGORIES` (display order GYMNASTICS → WEIGHTLIFTING → MONOSTRUCTURAL). Wrapped for screens by `hooks/use-exercises.ts`'s `useExercises()` (`{ exercises, loaded }`).
- `workouts.ts` — the only source of workouts. `Workout = { id, origin: 'builtin' | 'user', ownerId, config: WodConfig }` (`ownerId` is null for built-ins, and for a user workout only once its profile was deleted while a kept session still used it); `isOwn(workout, profileId)` is the one ownership check screens use. `listWorkouts(db)`: non-archived, `ORDER BY createdAt, rowid` (rowid keeps the v2 seed's FRAN → CINDY → EVERY MINUTE → FILTHY FIFTY order, since they share a `createdAt`). `getWorkout(db, id)`: any workout, archived included (saved sessions must keep resolving theirs), `null` if missing. Both parse the `blocks` JSON (`{ formatId, lines: [[{ exerciseId, target }]], rounds?, durationSeconds? }`) into a `WodDefinition`, resolving `formatId` through `wod-engine.ts`'s `FORMATS` (code, not the `formats` table) and exercise names through an *unfiltered* `exercises` lookup (an archived exercise must still name itself), then call `buildWodConfig`. Strict: more than one block, an unknown format or an unknown exercise throws — such rows can't exist until engine v2 widens the shape. Stored lines are `{ exerciseId, target, repDescription?, load? }` (`load` is free text, descriptive only). `createWorkout(db, { name, block, ownerId, derivedFrom })` (change `wod-editor`) inserts one new single-block `origin: 'user'` row (`makeId()`, `scoringBlock: 0`, `createdAt: Date.now()`, so it sorts after the built-ins) and returns its id — workouts are immutable, nothing ever updates one's content. `archiveWorkout(db, id, ownerId)` sets `archivedAt` only on a matching own `user` row, so a built-in can't be archived even by a screen bug. Wrapped for list screens by `hooks/use-workouts.ts`'s `useWorkouts()` (`{ workouts, loaded, refresh }`).
- `sessions.ts` — `saveSession(db, input)`: a single `withTransactionAsync` insert, returning the new row's id (B12 needs it to attach adjustments). Ids are a short local string (timestamp + random base36, `makeId()` — exported, reused by `profile.ts`/`session-adjustments.ts`), not a real UUID — the ROADMAP's UUIDv7 is an unconfirmed assumption, not a decision, and this is revisable later without migrating rows. `getSession(db, id)` reloads a saved row (events JSON parsed back to `StoredEvent[]`), for screens reached only by `sessionId` route param (`session/adjust.tsx`, `history/[id].tsx`). `getOwnSessions(db, athleteId)` (B23) is the same shape, filtered to `judgedAthleteId = athleteId` — exactly what `history/index.tsx` lists. `deleteSession(db, id)` (B23) removes a session and its `session_adjustments` in one transaction (same cascade pattern `profile.ts`'s `deleteProfile` uses).
- `profile.ts` — `getProfile`/`createProfile`/`updateAlias`/`deleteProfile` against the single-row `athlete_profile` table (B19). `deleteProfile` applies the decided retention rule in one transaction: deletes this profile's own sessions (and their `session_adjustments`) by `judgedAthleteId`, keeps foreign ones, then deletes the profile's own workouts — except any a kept foreign session still references (`sessions.wodId`), which become archived and owner-less so that session keeps resolving them (the foreign key would turn a mistake here into an error). Wrapped for screens by `hooks/use-profile.ts`'s `useProfile()` (`{ profile, loaded, refresh }`).
- `session-adjustments.ts` — `getAdjustments`/`addAdjustment` against `session_adjustments` (B12). `AdjustmentChange` is a `{ type: 'target', roundIdx, exIdx, newTarget }` / `{ type: 'duration', newDurationSeconds }` union, JSON-stored per row; `addAdjustment` enforces the decided 3-per-session cap in app code (the schema has no `CHECK` on `seq`).

### Shared UI

- `components/screen.tsx` — `Screen`: root wrapper every top-level screen uses instead of a bare `View`. Applies `useSafeAreaInsets()` as padding (status bar, notch, gesture bar) to its normal-flow children, inside a `KeyboardAvoidingView` (`behavior="padding"`): under edge-to-edge Android no longer resizes the window for the on-screen keyboard, so this is what keeps lower text fields visible on every screen. **Don't rely on this padding to offset a `position: 'absolute'` child** — confirmed on `my-qr.tsx` that it doesn't (the close button stayed under the status bar until it was moved into normal flow, see that file); give any top-corner interactive element its own header row in normal flow instead, like `my-qr.tsx` and `start-overlay.tsx` do. `minBottomPadding` gives a floor for screens whose last element needs room even with a zero inset. Doesn't set a background color — screens still own their own theme via `style` (`my-qr.tsx` is intentionally inverted, light-on-dark).

### Hooks

- `hooks/use-judge.ts` — `useJudge(config: WodConfig)` — holds the engine's `EngineState` (`constants/wod-engine.ts`) on the session clock: a 250 ms tick calls `advanceTo(Date.now() - sessionStart)`, each gesture first moves the clock to its own `t` (a gesture after a clock-driven end is dropped, never recorded) and then `apply`s the event, and everything shown (timer, exercise, count, KPI) comes from `view`. One `commit` path detects transitions to play the minute cue (EMOM) and end cue (any finish that isn't `isComplete`: AMRAP, EMOM and a For Time at its cap — finishing on the last rep is silent) and to stop the clock. `log` is the state's tagged events mapped back to `LogEntry`. Also owns the gestures (`Pan` + `Tap`, thresholds from the design) and the animated styles; return shape unchanged from the reducer days, so `session/run.tsx` didn't change
- `hooks/use-sound-cue.ts` — wraps a short local sound (`expo-audio`) in a stable, fire-and-forget `play()` callback
- `hooks/use-profile.ts` — `useProfile()`: loads the local `AthleteProfile` (`db/profile.ts`) on mount, exposes `{ profile, loaded, refresh }`. No shared context for this one — every screen that needs it calls this independently (unlike the session flow's `use-session.tsx`, this state isn't scoped to a route subtree, so a context wouldn't fit the same way)
- `hooks/use-first-run.ts` — `useFirstRun()`: same shape as `use-profile.ts`, wrapping `db/app-state.ts`'s `firstRunDone` flag (`{ done, loaded, markDone }`). Read by `app/index.tsx` to decide whether to push `/first-run`
- `hooks/use-exercises.ts` — `useExercises()`: loads the exercise catalog (`db/exercises.ts`) once on mount, `{ exercises, loaded }`. No `refresh` — nothing can change the catalog while the app runs yet. Read by `app/library/index.tsx` and the editor (`app/library/new.tsx`, for its exercise picker)
- `hooks/use-workouts.ts` — `useWorkouts()`: wraps `db/workouts.ts`'s `listWorkouts`, `{ workouts, loaded, refresh }` — loads on mount, and the two lists (`library/index.tsx`, `session/wod.tsx`) call `refresh` in a `useFocusEffect`, since they stay mounted under the editor/detail where workouts get created and archived
- `hooks/use-session.tsx` — the project's first React context. `SessionProvider` (mounted by `app/session/_layout.tsx`, so its state's lifetime is exactly the `session/` group's mount lifetime — popping out to the hub clears it for free, no manual reset needed) + `useSession()` (throws outside the provider). Holds `workout` (`{ id, config }`, written by `session/wod.tsx` on pick — workouts are immutable, so this snapshot can't go stale), `setup` (`{ role, otherId, otherAlias }`, written by `session/setup.tsx`), `outcome` (`{ log, startedAt, endT }`, written by `session/run.tsx` once judging finishes) and `sessionId` (written by `session/result.tsx` once saved) — this is what lets `run.tsx` hand off the raw judging log to `result.tsx` across a real route boundary, instead of trying to serialize it into a URL param
